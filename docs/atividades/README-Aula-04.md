# Aula 04 — Arquitetura, separação de responsabilidades, refatoração, teste e ADR

## Objetivo
Reconhecer a necessidade de estrutura arquitetural, separar responsabilidades e registrar a decisão, preservando o comportamento por meio de teste.

## Atividade no projeto do grupo

1. Identifique no projeto uma situação real do FinCore que envolva o assunto desta aula.
2. Registre o problema/necessidade antes de escolher a solução.
3. Produza os artefatos solicitados abaixo com nomes e exemplos do próprio domínio.
4. Quando houver mudança de código, compile e execute os testes antes de concluir.
5. Registre no GitHub a evidência da atividade (Issue/branch/commits/PR).


## Onde registrar
- `docs/arquitetura/arquitetura-atual.md`
- próximo ADR sequencial em `docs/adr/`
- `docs/evidencias/aula-04/`

Consulte `docs/README.md` se tiver dúvida sobre a pasta correta.

## Não fazer
- Não introduzir tecnologia ou mecanismo sem justificar o problema que ele resolve.
- Não alterar código sem preservar/verificar o comportamento esperado.

# Entrega — Aula 04
- Diagnóstico de uma classe/módulo com responsabilidade mal definida ou excessiva.
- Antes/depois da responsabilidade de cada elemento.
- Código refatorado quando aplicável.
- Compilação bem-sucedida.
- Pelo menos um teste JUnit relacionado à regra preservada ou modificada.
- `próximo ADR sequencial` em `docs/adr/`, usando `docs/modelos/ADR-MODELO.md`.
